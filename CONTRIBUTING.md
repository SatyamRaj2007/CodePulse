# Contributing to CodePulse

## Development Workflow

CodePulse follows a feature-branch workflow.

1. Pick or create a GitHub Issue.
2. Create a feature branch.
3. Implement the feature.
4. Test the changes.
5. Commit using a meaningful commit message.
6. Push the branch.
7. Open a Pull Request.
8. Address review feedback.
9. Get approval.
10. Merge the Pull Request.

## Branch Naming

Use:

- `feature/<name>`
- `fix/<name>`
- `refactor/<name>`
- `docs/<name>`
- `test/<name>`

Examples:

- `feature/auth-api`
- `feature/dashboard`
- `fix/profile-validation`

## Commit Convention

Use prefixes such as:

- `feat:`
- `fix:`
- `docs:`
- `test:`
- `refactor:`
- `chore:`

Examples:

`feat: add user registration API`

`fix: handle invalid profile URL`

`docs: update setup instructions`

## Pull Requests

Every Pull Request should:

- Explain what changed.
- Reference the related Issue.
- Include testing information.
- Keep the scope focused.
- Address reviewer feedback before merging.
